# WF-1 AI Project Chat — Implementation Plan

> **For Hermes:** Use subagent-driven-development skill to implement this plan task-by-task.

**Goal:** Read-only, stateless, membership-gated chat endpoint per project that answers questions grounded in DB facts, reusing the narration pipeline from project summaries.

**Architecture:** New `AiService.chat()` builds a compact context block (project stats + recent activity, identical aggregates the summarizer already queries), sends it with conversation history through `_narrative_call` (free-text, one empty-retry). Endpoint `POST /ai/projects/{project_id}/chat` mirrors `summarize_project`: `get_current_membership` + `get_generating_service`, visibility enforced inside the service via `_projects.get_accessible`. Streaming is a transport detail over the same result.

**Tech stack:** FastAPI, existing repos, existing `LLMClient.complete()` protocol — no new deps, no new exceptions, no new Settings.

---

## Decisions locked (Q7–Q15)

- **Read-only / stateless:** no persistence, no activity records, no conversation storage. Client supplies `history`.
- **Grounding:** model receives ONLY aggregates within caller's visibility (same rule as summaries) plus explicit "answer only from this context" system prompt.
- **Placement:** service method in `app/ai/service.py`; prompt constant in `app/ai/prompts.py`; endpoint in `app/api/v1/endpoints/ai.py`.
- **Errors:** no new types. `AiNotConfiguredError`→503 (via `_require_llm` after visibility check), `AiUpstreamError`→502, body validation→422 unified envelope. Existing handlers in `app/core/exceptions.py` + global handler already map these.
- **Config:** code constants `AI_CHAT_MAX_HISTORY_MESSAGES = 10` in prompts or service module; no Settings churn.
- **Streaming:** response is SSE (`text/event-stream`) only if client opts in (request flag); default JSON `{answer, citations?, model}`. V1 streams the COMPLETED answer as chunks — no protocol change, `ScriptableLLM` unaffected.

# --- chatting (AI V2: read-only Q&A over the same narrated facts) ---

async def chat(
    self,
    *,
    actor: User,
    actor_membership: Membership,
    project_id: uuid.UUID,
    question: str,
    history: list[dict],
) -> ChatResponse:
    self._require_llm()                      # 503 AFTER visibility? No — see order below
    project = await self._projects.get_accessible(
        project_id,
        actor_membership.organization_id,
        user_id=actor.id,
        sees_all=is_manager_or_above(actor_membership),
    )
    if project is None:
        raise NotFoundError(message="Project not found.")

    context = await self._chat_context(project)   # private helper, Task 4
    convo = self._trim_history(history)           # last N turns, alternating roles
    user_msg = context + "\n\n" + "\n".join(convo) + f"\nUser: {question.strip()}"

    answer = await self._narrative_call(
        system=PROMPT_PROJECT_CHAT_V1, user=user_msg
    )
    return ChatResponse(project_id=project.id, question=question.strip(), answer=answer)
```

Order note: call `_require_llm()` FIRST (mirrors `generate_project_summary`) — an unconfigured provider 503s regardless of whether the project exists, which also avoids leaking existence to unauthorized callers. Matches the stated Q13 decision ("still fires after the membership guard").

def _trim_history(self, history: list[dict]) -> list[str]:
    kept = history[-AI_CHAT_MAX_HISTORY_MESSAGES:]
    return [
        f"{'Assistant' if m['role'] == 'assistant' else 'User'}: {m['content']}"
        for m in kept
        if m.get("role") in ("user", "assistant") and m.get("content")
    ]

async def _chat_context(self, project) -> str:
    """Same aggregates the summarizer narrates — nothing outside caller
    visibility, never raw rows."""
    now = datetime.now(UTC)
    today = now.date()
    status_counts = await self._tasks.status_counts(project.id)
    total = sum(status_counts.values())
    completed = status_counts.get("COMPLETED", 0)
    workload = await self._tasks.open_workload_top(project.id)
    activity_rows, _ = await ActivityRepository(self._session).list_for_project(
        project.id, page=1, limit=8
    )
    stats = ProjectStats(
        total_tasks=total,
        status_counts=status_counts,
        progress_pct=round(completed / total * 100) if total else 0,
        overdue_count=await self._tasks.overdue_count(project.id, today),
        unassigned_high_urgent_count=await self._tasks.unassigned_high_urgent_count(project.id),
        due_within_week_count=await self._tasks.due_within_week_count(project.id, today),
        stale_open_tasks_count=await self._tasks.stale_open_count(
            project.id, cutoff=now - timedelta(days=5)
        ),
        workload_top=[WorkloadEntry(**w) for w in workload],
        recent_activity=[
            ActivitySample(action=a.action, created_at=a.created_at)
            for a, _ in activity_rows
        ],
    )
    return (
        f"Project: {project.name}\n"
        f"Project facts (JSON):\n"
        f"{json.dumps(stats.model_dump(mode='json'), indent=1)}"
    )
```

class ChatHistoryItem(BaseModel):
    role: Literal["user", "assistant"]
    content: SafeStr = Field(min_length=1, max_length=4000)

class ChatRequest(BaseModel):
    question: SafeStr = Field(min_length=2, max_length=2000)
    history: list[ChatHistoryItem] = Field(default_factory=list, max_length=20)

class ChatResponse(BaseModel):
    project_id: uuid.UUID
    question: str
    answer: str
    model: str | None = None   # omit or fill from llm client if it exposes it; None ok in V1

(`max_length=20` on history lets the endpoint accept slightly more than the trim cap without 422 noise.)

**Step 2: Endpoint** (in `endpoints/ai.py`, after `summarize_project`; add `stream: bool = False` query param reserved for Task 6):

```python
@router.post("/ai/projects/{project_id}/chat", response_model=ChatResponse)
async def chat_with_project(
    project_id: uuid.UUID,
    payload: ChatRequest,
    context: tuple[User, Membership] = Depends(get_current_membership),
    service=Depends(get_generating_service),
    stream: bool = False,

    return await service.chat(
        actor=actor,
        actor_membership=membership,
        project_id=project_id,
        question=payload.question,
        history=[h.model_dump() for h in payload.history],
    )
```

Note: NO manager gate at the endpoint — visibility comes from `get_accessible(sees_all=...)`, same as `summarize_project`. Members can chat about projects they can see.

if stream:
    async def event_gen():
        # V1: chat() resolves fully, then we emit it as SSE data events.
        # True token-level streaming would need stream() on the LLMClient

## Risks / tradeoffs

- **Context duplication vs extraction:** prefer extracting `_project_stats()` shared with the summarizer; small refactor, big DRY win, covered by existing summary tests.
- **V1 streaming is pseudo-streaming** (chunks of a completed answer). Honest about it in the ticket; real token streaming = protocol change (`stream()` on LLMClient), deferred to WF-backlog.
- **History injection:** history contents are user-controlled text placed into the user message — acceptable because output is freeform narration shown only to the requesting member (no downstream parsing/persistence). The "answer ONLY from context" prompt mitigates prompt-injection drift but does not eliminate it; stateless read-only scope caps the blast radius.
